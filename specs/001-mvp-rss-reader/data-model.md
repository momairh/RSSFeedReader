# Data Model: MVP RSS Feed Reader

**Feature**: 001-mvp-rss-reader | **Date**: 2026-09-04

## Overview

The MVP has a single entity, `Subscription`, held in memory for the lifetime of the backend process. There are no relationships, no foreign keys, and no database schema.

## Entity: Subscription

Represents one feed the user has subscribed to.

| Field | Type | Required | Description | Source requirement |
|---|---|---|---|---|
| `Id` | `Guid` | Yes | Unique identifier generated by the store when the subscription is created | FR-011 |
| `Url` | `string` | Yes | Feed URL exactly as entered by the user (trimmed of leading/trailing whitespace) | FR-001, FR-012 |
| `AddedAt` | `DateTimeOffset` | Yes | UTC timestamp recorded when the subscription is created | FR-011 |

### Validation rules

| Rule | Enforcement | Requirement |
|---|---|---|
| `Url` must not be null, empty, or whitespace-only | API returns HTTP 400; UI blocks submission | FR-003, FR-004 |
| `Url` length must be 2,048 characters or fewer (after trimming) | API returns HTTP 400 | FR-015 |
| `Url` is not validated as a well-formed URI or a real RSS/Atom feed | Intentionally not enforced | FR-012 |
| Duplicate `Url` values are permitted | Intentionally not enforced | Edge case: duplicates |

### Lifecycle

- **Create**: `POST /api/subscriptions` → store generates `Id` and `AddedAt`, appends to the list.
- **Read**: `GET /api/subscriptions` → returns all subscriptions in insertion order (newest last, FR-009).
- **Update**: Not supported in the MVP.
- **Delete**: Not supported in the MVP (post-MVP scope).
- **Destroy**: All subscriptions are discarded when the backend process stops (FR-010).

## Storage model

```text
ISubscriptionStore (abstraction)
├── IReadOnlyList<Subscription> GetAll()
└── Subscription Add(string url)

InMemorySubscriptionStore (MVP implementation, registered as singleton)
├── private readonly List<Subscription> _subscriptions
└── private readonly object _syncRoot   // guards mutation and snapshot enumeration
```

- Registered as a **singleton** so state survives across requests within the process.
- `GetAll()` returns a snapshot copy taken under the lock, so callers cannot mutate internal state or observe a torn list.
- `Add()` appends under the lock, guaranteeing that concurrent adds are both stored and that insertion order is preserved.

## Data transfer objects

### AddSubscriptionRequest (client → API)

| Field | Type | Description |
|---|---|---|
| `url` | `string` | The feed URL entered by the user |

```json
{ "url": "https://devblogs.microsoft.com/dotnet/feed/" }
```

### SubscriptionResponse (API → client)

| Field | Type | Description |
|---|---|---|
| `id` | `string` (GUID) | Unique identifier |
| `url` | `string` | Feed URL |
| `addedAt` | `string` (ISO 8601) | When the subscription was added |

```json
{
  "id": "8f14e45f-ea4e-4b1c-9c39-3f6e0a4b1f2d",
  "url": "https://devblogs.microsoft.com/dotnet/feed/",
  "addedAt": "2026-09-04T15:42:11.123+00:00"
}
```

## Future model (deferred, not implemented)

When persistence and feed fetching arrive in later phases, this model is expected to grow with a `FeedItem` entity (title, link, published date, owning subscription) and a one-to-many relationship from `Subscription` to `FeedItem`. Because all access goes through `ISubscriptionStore`, swapping the in-memory implementation for an EF Core implementation will not change controllers or UI code.
